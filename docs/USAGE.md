# 使用与数据说明

安装和启动步骤见根目录 README.md，Linux 部署见 deploy/BAOTA.md。

## 系统账号与主播端

首次启动自动创建管理员 `admin`，随机初始密码位于 `data/initial-admin.txt`，不会通过网页接口返回。登录后可在右上角修改密码、退出登录。忘记主播密码时由管理员重置；当前没有邮件找回或公开注册。

管理员在“主播与账号”对应主播旁点击“开通登录账号”，填写登录名和至少6位密码。每位主播对应一个系统登录账号，可通过“管理登录账号”重置密码、停用或恢复登录。修改登录账号后会撤销该用户已有会话。

主播和管理员使用同一网址登录，按身份进入各自工作台。主播只能查看自己名下的日报、月报、历史合计、场次明细和同步记录，以及导出自己的数据；可手动同步、补采、添加和重新扫码自己的抖音号。无权管理其他主播、修改账号归属、审核绑定、修改全局定时设置或停止全局任务。所有账号接口（包括二维码、验证窗口和登录检测）、报表及 CSV 导出均在后台校验归属。

主播新增的抖音号自动归到本人名下，状态为“绑定待审核”。完成扫码后，管理员核对昵称和账号归属，点击“审核通过”才允许采集；拒绝后保留记录，不参与采集。系统通过官方页面加载的字符串用户ID核对身份，保存昵称以及明确识别到的公开抖音号，不保存该响应的其他个人资料。重复绑定同一抖音号、重新扫码换成不同身份均会被阻止；首次扫码无法证明账号真实所有权，仍由管理员审核。

登录密码使用加盐 scrypt 哈希保存，系统会话以随机令牌建立，数据库只保存令牌哈希。会话有效期12小时，Cookie 为 HttpOnly、SameSite=Strict；修改密码、停用账号和退出登录会撤销相应会话。初始密码文件属于敏感资料，请在修改密码后移除。抖音登录状态与系统登录会话分别保存。

扫码遇到短信或安全验证时，原弹窗自动切换到官方验证区域，支持点击、拖动和输入验证码。验证码仅传入当前登录窗口，不写入数据库或日志；验证仍由本人完成。验证截图和输入接口同样检查账号归属。日常扫码界面继续只显示二维码。

内部使用已移除输错密码次数限制；登录、密码校验、会话有效期及主播权限隔离保留。

## 首次使用

1. 在“主播与账号”添加主播名称、备注。
2. 在该主播下点击添加抖音号，只需选择所属主播、填写可选备注，点击“保存并扫码”。登录后自动读取官方昵称和公开抖音号；未识别到抖音号时隐藏该项，不使用昵称或用户ID冒充抖音号。
3. 显示“已登录”后点击“立即同步”，或在“补采数据”选择日期范围。
4. 在“直播数据”选择月份，可以筛选主播/账号、展开每天场次并导出 CSV。

二维码从账号专用浏览器里的官方登录组件裁剪，包括组件位于 iframe 的情况；允许二维码中央的官方图标，不允许覆盖二维码的验证或过期遮罩。排队时说明当前等待原因，加载超过30秒给出刷新或打开官方登录页的提示。扫码和验证均使用无界面浏览器，不弹出独立浏览器窗口。需要身份验证时自动在原弹窗展示官方验证界面，并尽量裁剪到验证框；裁剪区域点击坐标经后台按账号映射到原页面。识别到官方短信验证时，显示网站自己的“获取验证码”和验证码输入框；填写6位验证码后点击“验证登录”，后台自动填入并点击官方验证按钮，无需手动选择官方输入框。重新发送遵守官方倒计时，并显示验证码错误提示；也可切换到官方界面处理其他验证方式。验证码仅用于本次官方验证，不写入日志或数据库。刷脸等手机操作仍须按平台指引完成。完成手机确认/验证后，停止展示官方后台画面；核对账号身份、关闭独立浏览器以保存登录环境后，扫码弹窗自动关闭并更新账号列表。重复绑定或身份不符会明确显示原因，不会被当作登录成功，也不会继续展示官方后台。

## 统计口径

管理员在“主播与账号”点击对应主播的“组长与归属”，可将主播设为组长，或将普通主播归属某位组长。每位主播最多归属一名组长；组长不再归属其他组长。取消组长前须先调整名下主播归属。

组长使用原有登录账号，查看自己及直接归属主播的直播数据、月度保底进度、同步记录和保底提醒；报表、场次、历史合计及 CSV 导出均按这一范围限制。组员的抖音号为只读，不能替组员扫码、修改账号或发起采集。普通主播仍只能查看和操作自己的账号。月度保底始终仅由管理员设置。更改归属立即影响后续接口请求，网页每5秒刷新权限与数据，不需要重新登录；历史数据随主播当前归属展示。

- 北京时间（Asia/Shanghai），每月 1 日至最后一天。
- 跨午夜、跨月直播按开播日期归属；直播时长按单场提供的秒数累计，不使用日历上按分钟显示的汇总。
- 每个主播名下全部账号的场次相加；即使账号同时开播，也分别累计时长。
- 新增粉丝为按场累计，非净增粉丝；送礼人数也按场累计，不跨场或跨账号去重。
- 加粉丝团人数、评论人数按单场官方复盘采集，按日、月和保留期累计，不跨场或跨账号去重。缺少新指标且仍在本地保留范围、最近90天内的日期会纳入自动补采；缺失字段不会当作0。场次明细支持选择日期及导出当天全部场次。
- 曝光人数、进房人数按场累计，不跨场去重；单场进房率使用官方百分比，日/月/历史汇总进房率以总进房人数除以总曝光人数计算，不平均单场百分比。旧数据未采集显示“未采集”，真实零曝光且零进房显示0%。
- 场次 ID 始终保存为字符串，避免长整数精度损失。同一场重复同步会更新数值，不再次累计。
- 全库的场次 ID 唯一，避免同一抖音账号被重复绑定后重复统计。
- 调整账号归属后，该账号历史数据一并归入新主播。
- 未采集、部分采集、确认无直播、今日暂计、未来待结算分别显示。今日快照不会提前算作最终日报，次日完整复查后才计入已核对天数。月合计包含已保存的今日数据。
- 完整率按每个账号的统计起始日、审核状态和是否启用计算。待审核、拒绝、未到统计起始日或暂停的账号不增加应采集数量；已有采集记录和历史指标保留。管理员可在编辑抖音号时修改统计起始日。

## 自动同步与登录

默认每5分钟更新今天和昨天，间隔可选1、3、5、10、15、30分钟，也可手动同步今天；排队繁忙时按顺序执行。每天北京时间04:00另做历史核对，回查本地保留范围与最近90天交集内的缺失日期及最近3天。不会自动重新采集已按保留规则清理的旧月份。实时更新基于官方复盘可用数据，直播中指标不是秒级推送；明确标记直播中的场次等待复盘后采集。统计起始日默认添加账号当月1日，手动补采保留期内的更早日期成功后会向前扩展。

服务进程必须运行，机器需要开机、联网。关闭网页不影响后台任务，关闭服务器或机器则不能执行。重启后会检查当天是否错过任务。`scripts/install-autostart.ps1` 可安装当前 Windows 用户登录后自动运行的守护任务，后端进程退出后5秒重启。不会自动登录 Windows；安装和服务器配置见 `../deploy/README.md`。

同步、补采、扫码和登录检测进入持久化任务队列，相同的等待中或处理中请求去重，同时最多运行两个独立浏览器任务：可两个账号扫码，或一个账号扫码、另一个账号同步/检测。后台同步与检测仍串行，同一账号始终互斥，第三个任务排队。此上限面向4核4GB服务器保守设置，实际承载能力仍取决于系统和其他服务占用。扫码优先于尚未开始的登录检测和同步，登录检测优先于同步；不打断正在执行的任务。排队期间修改归属或停用系统账号，执行前会重新校验权限。等待中的任务可取消；服务重启会恢复同步与检测任务，进行中的扫码需重新发起。临时网络和加载错误最多尝试3次，间隔30秒、120秒；身份验证和数据格式错误不会无限重试。

“任务队列”只显示等待中和处理中的任务，“同步记录”显示采集执行结果。记录列表每页最多15条。同步记录、已结束任务、登录检测、操作审计和通知只保留最近7天；采集诊断截图、诊断文件与按日写入 `data/runtime-logs/` 的应用日志也清理7天前的文件。单日应用日志上限10MB，旧版进程输出文件超过5MB时截断。未完成任务不删除。

直播明细和日期采集记录仅保留当月及前两个月，例如2026年9月保留7月1日起的数据。服务启动和运行期间自动清理，数据库每天最多整理一次以回收空闲空间。主播、账号、Cookie和保底设置不受影响；“本地保留数据累计”只合计尚在本地的记录。备份仍单独按原规则保留最近30份，旧备份可能含有更早数据，可由管理员在数据备份中删除。

旧月份显示“需在线重新提取”，管理员或账号本人可使用“在线重新提取”/“补采数据”按需查询，一次最多100天。查询使用官方页面正常日历操作，成功结果只进入内存临时表，30分钟后过期，服务重启也会清除，可在有效期间查看及导出。临时记录不写入数据库或新备份，不改变统计起始日，不加入本地保留数据累计；仍遵守主播/组长权限。旧月份不显示缺少历史数据的保底完成结论。实际可查时间取决于抖音官方页面；不再提供或禁止选择的历史无法保证恢复，不绕过平台限制。

管理员可在“主播与账号”或“直播数据”的保底区域，按主播、按月份设置直播保底小时和分钟。保底按该主播全部抖音号的已采集时长合计，显示未设置、还差多少、已达标或超出多少。“通知中心”仅保留保底未达标提醒：北京时间每月最后7天，未达标主播每天最多一条，重启或刷新不重复生成，达标后标为已恢复；未设置保底不提醒。服务离线期间不发送，恢复后仅生成当天符合条件的提醒。登录和同步异常仍可在账号状态及同步记录查看。

每个账号使用 `data/profiles/<账号ID>/` 下独立的浏览器配置，不会读取用户日常浏览器的 Cookie。常规账号接口不返回 Cookie。会话有效期由抖音决定；过期或验证要求会停止该账号采集并显示重新登录。已保存唯一身份的账号按身份核对，改昵称不会视为换号；旧数据尚无唯一身份时先核对已有昵称，再补充身份记录。

管理员可在“主播与账号”中点击某一账号的“导出 Cookie”，下载 Cookie-Editor 支持的 JSON 数组；普通主播和组长没有此权限。导出只包含该账号保存的 douyin.com 及其子域 Cookie，保留域名、路径、HttpOnly、SameSite 和有效期，过滤已过期 Cookie；扫码、同步、检测和导出期间互斥，不触发数据采集。操作记录仅保存账号、操作人和 Cookie 数量，不记录 Cookie 内容。打开 `https://anchor.douyin.com/`，用 Cookie-Editor 的 Import 粘贴 JSON 文件全文后导入，刷新页面。文件包含登录凭据，请仅在自己的浏览器中使用。导出不保证抖音允许在其他设备复用登录状态。

“主播与账号”中，每个账号的“检测登录状态”按钮使用保存的登录环境实际访问抖音后台，显示登录有效、登录失效、需要验证、需核对账号或无法确认，并保存检测时间。点击“检测记录”可查看最近 10 次结果。网络、浏览器或页面加载异常只记录为无法确认，不据此判定 Cookie 失效。同一账号的检测与扫码、同步互斥；不同账号可在两个浏览器名额内同时扫码，或扫码与一次检测/同步同时运行。检测不采集直播明细，也不清除原有同步错误。可以在其他浏览器登录前后分别检测；状态变化本身不能证明失效一定由异地登录引起，也不代表平台保证多端长期同时在线。

## 采集实现及边界

当前使用 Playwright 操作官方复盘网页，不依赖未经验证的私有 API：按日选择日历、遍历并滚动场次列表、读取每场复盘。指标以完整整数读取，缺失值、破折号、缩略数字（如 `1.2万`）不会当成 0 或估算写入。平台改变 DOM 结构、持续加载、触发验证或返回不完整结果时，会记录失败而不是伪造成功。

读取范围限定在“开播场次”面板，排除 DOM 中隐藏的“连线场次”。采集等待页面实际发出的场次列表、指标请求完成，不等待整个网页网络空闲；后台心跳不会阻塞任务。数据接口失败时不把空白页面记作零直播。订阅复盘提示弹窗出现时仅关闭提示。

选择日期前先等待默认列表请求完成，选择后等待起止日期均与目标日期一致的场次响应，并核对实际显示的列表。日期标题已变化但场次仍未更新时继续等待，避免把默认列表误归到某一天，或把尚未加载的场次记为零。

平台对零时长场次可能省略详情时长。只有列表明确显示 `0秒`，且开播/关播时间完全相同时，才记录为零时长。其他缺失时长仍会报错。

场次通过事务写入，当天数据仅保存快照；过往日期完整读取且没有正在直播的场次时才标记已核对。已保存的今日快照跨午夜后会再次复查，不会直接当作完整日报。完整复查场次少于已保存数量时保留旧数据并报告异常。列表通过滚动到底后连续稳定检查确认加载结束，另有滚动次数上限。

管理员可在“主播与账号”点击抖音号右侧删除按钮。统一输入“确认删除”后才能删除，无需填写抖音号。删除前自动生成数据库备份，任务执行期间拒绝删除。删除会清理该号的历史场次、覆盖记录、同步和检测记录、通知、排队任务及本机浏览器登录环境；主播合计随之减少。主播及其网站登录账号保留，操作记录保留删除审计。备份不包含浏览器登录环境，恢复后可能需要重新扫码。

## 数据与维护

- 数据库：`data/live.sqlite`（SQLite WAL 模式）。
- 登录环境：`data/profiles/`。其中包含敏感登录状态，不要上传或分享。
- 停止服务后可备份整个 `data` 目录；运行中不要仅复制单个 SQLite 文件而遗漏 WAL。
- 测试使用独立临时数据库，不会向正式数据库添加示例数据。
- 每日自动生成一致性数据库快照，保留最近30份；管理员可在“数据备份”创建、校验和下载备份及校验文件。恢复脚本会校验 SHA-256、数据库完整性和外键，写入新文件，不覆盖现有数据；恢复后撤销系统会话和旧任务。具体步骤见 `../deploy/README.md`。浏览器登录环境需停采后另行备份。

```powershell
npm.cmd test
npm.cmd run test:ui
npm.cmd run test:teams
```

测试覆盖自然月/闰年、北京时间、跨月场次、多账号汇总、重复同步、账号调整归属、缺失与零值、事务回滚、定时触发、CSV 公式防护、滚动加载、登录失效、二维码 iframe 裁剪，以及 390/768/1440 像素视口的页面和表单流程。截图和测试报告位于 `test-output/`。
